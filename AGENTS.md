# DCIM project context

Read `PROJECT_CONTEXT.md` at the start of a new session for the product goals,
architecture, prior decisions, and handoff from the original Claude conversation.
Treat historical verification as historical: check current code and runtime before
claiming that the app is running or tests pass. Keep that document current when
product decisions or implementation status materially change.

Read `docs/PRODUCT_PLAN.md` before proposing or starting new product features.
It distinguishes agreed direction, proposed Day 1 scope, and deferred ideas.
Keep roadmap recommendations distinct from user-approved implementation work.
